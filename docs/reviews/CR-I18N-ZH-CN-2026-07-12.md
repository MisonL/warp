## 2026-08-03 Linux 在线测试网络修复

首次在线测试失败的直接原因是远程 SSH 登录环境未继承本机 Mihomo 的代理变量。Linux 主机将 `github.com` 解析为 Fake-IP `198.18.0.16`，未设置代理时直连 `github.com:443` 超时，因此 Cargo 无法获取固定的 Git 依赖；这不是本地化源码或 Cargo manifest 错误。

修复方式仅对本次测试进程注入远程主机已有的本地 HTTP 代理，不修改项目依赖或 Linux 全局配置：

```text
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
ALL_PROXY=http://127.0.0.1:7890
CARGO_NET_GIT_FETCH_WITH_CLI=true
CARGO_TARGET_DIR=/tmp/warp-i18n-20260803-target
CARGO_BUILD_JOBS=2
```

在 `/tmp/warp-i18n-20260803-current` 使用 Rust 1.93.0 重跑：

```text
timeout --signal=TERM --kill-after=20s 1800s cargo test -p warp_localization --tests -- --test-threads=1
```

结果：退出码 `0`，`96 passed, 0 failed`，耗时约 23 秒；`tink-rust`、`warp-proto-apis`、`notify`、`winit` 等固定 Git 依赖均成功获取并完成编译。该结果闭合了此前 Linux 外部网络门禁，后续远程在线测试必须以同样的进程级代理环境运行，不能把未设置代理的直连失败归因于项目代码。
